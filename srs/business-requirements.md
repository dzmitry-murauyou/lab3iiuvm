## 1. Выбор приложения и типа проекта (задание 1)

| Параметр | Решение для курсового проекта |
|----------|-------------------------------|
| **Название проекта** | **KeyNest** («КейНест») — «Гнездо для ключей» |
| **Предметная область** | Менеджер паролей: генерация и хранение паролей, автозаполнение, категории, заметки, двухфакторная аутентификация |
| **Тип проекта** | Настольное **Desktop-приложение**, offline-first, один пользователь — одно устройство — одно хранилище |
| **Внешние сервисы** | По умолчанию **отключены**; опционально: (1) HIBP Pwned Passwords API — проверка утечек по k-анонимности (передаются только 5 символов SHA-1), (2) GitHub Releases — только уведомление об обновлении. Локальные «сервисы» ОС: хранилище ключей, системные часы, буфер обмена |
| **Предпочтительные технологии** | Java 17 LTS, JavaFX 21 (GUI), Maven, SQLite/локальный файл `vault.knx`, AES-256-GCM, Argon2id, RFC 6238 (TOTP), Jackson, SLF4J, JUnit 5, jpackage |
| **Язык разработки** | **Java 17** (основной), SQL/JSON для данных, Markdown + SysML v2 для документации и моделей |
| **Язык описания** | Русский и английский (документы SRS/BRD), язык SysML v2 (текстовая нотация) для моделей и макетов GUI; интерфейс приложения RU/EN |
| **Границы продукта** | Локальный зашифрованный файл, до 1000 записей; без облачной синхронизации, без сервера, без мобильных клиентов и расширений браузера в v0.1; Windows 10/11 и Linux x86_64 (macOS — R3+) |
| **Бюджет и сроки** | 0 BYN, только открытые библиотеки; один учебный семестр 2026/2027, три инкремента R1/R2/R3 |
| **Лицензия** | MIT для собственного кода, `NOTICE.md` для зависимостей |

**Обоснование выбора.** Заказчику нужен несложный, но реально полезный продукт: сейчас пароли хранятся в текстовом файле и записках, повторно используются на разных сайтах, а вход в 20+ сервисов занимает время. Менеджер паролей даёт измеримый эффект (безопасность + скорость) и в то же время реализуем за семестр. Выбор Java обусловлен планом студента писать код на Java, а JavaFX даёт кроссплатформенный Desktop GUI без веб-стека. Отказ от облака упрощает безопасность и делает проект независимым от внешней инфраструктуры — это отдельное бизнес-требование BR-10.

**Легенда интервью с Заказчиком.** «У меня 12 сотрудников и около 30 сервисов: почта, банк, GitHub, CRM, хостинг. Пароли записаны в файле на рабочем столе, половина из них одинаковые. Хочу один инструмент, который сам придумывает сложные пароли, подставляет их, раскладывает по папкам и показывает коды 2FA. Облаку не доверяю — пусть всё лежит на моём компьютере. Важно, чтобы я не потеряла доступ, если сотру телефон с кодом 2FA».

## 3. Бизнес-цели

| ID | Цель | Показатель успеха |
|----|------|-------------------|
| BG-01 | Не допускать утечки и повторного использования паролей | 0 паролей в открытом виде на диске; доля повторных паролей в аудите < 10 % к релизу R3 |
| BG-02 | Ускорить ежедневный вход в сервисы | поиск записи ≤ 200 мс, автозаполнение ≤ 2 с; время входа сокращается с ~40 с до ~10 с |
| BG-03 | Сохранить независимость от облака и вендоров | все ключевые функции работают без сети; перенос данных — одним зашифрованным файлом |
| BG-04 | Уложиться в рамки курсового проекта | три инкремента за семестр, бюджет 0 BYN, покрытие требований трассировкой 100 % |

## 4. Бизнес-требования Заказчика (BR-01…BR-10)

Приоритеты: **MUST** — обязательно, **SHOULD** — желательно, **COULD** — можно отложить. Трассировка к требованиям SRS — [srs-template.md](srs-template.md), раздел 3 и приложение B.

| ID | Требование | Формулировка (голос Заказчика) | Обоснование | Приоритет | Критерий приёмки | Релиз | Трассировка |
|----|------------|--------------------------------|-------------|-----------|------------------|-------|-------------|
| BR-01 | Локальное зашифрованное хранилище | «Я хочу открывать все пароли одним мастер-паролем, и чтобы файл нельзя было прочитать без него» | BG-01 | MUST | без пароля записи не читаются; 5 неверных попыток → задержка 30 с | R1 | REQ-FUNC-001, REQ-SEC-001…004 |
| BR-02 | Генерация паролей | «Пусть программа сама придумывает сложные пароли, а я выбираю длину и символы» | BG-01, BG-02 | MUST | длина 8–64, 4 набора символов, оценка энтропии | R1 | REQ-FUNC-003 |
| BR-03 | Записи с реквизитами | «Для каждого сервиса нужна карточка: логин, пароль, сайт, папка, заметка» | BG-02 | MUST | CRUD работает для 1000 записей | R1 | REQ-FUNC-004 |
| BR-04 | Автозаполнение | «Чтобы не копировать пароли руками, пусть подставляет их по горячей клавише» | BG-02 | MUST | `Ctrl+Shift+K` → панель ≤ 2 с, буфер очищается через 30 с | R2 | REQ-FUNC-008 |
| BR-05 | Категории и поиск | «Я хочу папки "Работа", "Финансы" и быстрый поиск по названию/логину» | BG-02 | MUST | поиск ≤ 200 мс на 1000 записей | R1 | REQ-FUNC-005, REQ-FUNC-006 |
| BR-06 | Заметки к записи | «Рядом с паролем нужны подсказки и коды восстановления» | BG-02 | SHOULD | до 2000 символов, шифруются вместе с паролем | R1 | REQ-FUNC-007 |
| BR-07 | Двухфакторная аутентификация | «Нужны коды 2FA для сайтов и второй фактор для самого хранилища» | BG-01 | MUST | TOTP 6 цифр / 30 с, ключ восстановления | R2 | REQ-FUNC-002, REQ-FUNC-009 |
| BR-08 | Резервные копии и перенос | «Если сломается ноутбук, я должна восстановить пароли и перенести их на другой ПК» | BG-03 | MUST | зашифрованный экспорт/импорт CSV, восстановление без потерь | R2 | REQ-FUNC-010, REQ-FUNC-011 |
| BR-09 | Аудит паролей | «Покажи, где пароли слабые или повторяются» | BG-01 | SHOULD | отчёт по слабым/повторным/старым паролям, HIBP — по согласию | R3 | REQ-FUNC-012 |
| BR-10 | Работа без сети и приватность | «Пусть всё работает без интернета и без регистрации в облаке» | BG-03 | MUST | офлайн-режим покрывает R1 и R2; телеметрии нет по умолчанию | R3 | REQ-AVAIL-001 |

## 5. Бизнес-правила

| ID | Правило |
|----|---------|
| BR-RULE-01 | Мастер-пароль — не менее 12 символов; не сохраняется на диске |
| BR-RULE-02 | Ключ восстановления — 24 символа, одноразовый, показывается один раз при создании хранилища |
| BR-RULE-03 | Авто-блокировка хранилища через 5 минут простоя, при сворачивании и при блокировке экрана |
| BR-RULE-04 | Скопированный пароль удаляется из буфера обмена через 30 с |
| BR-RULE-05 | 5 неудачных попыток ввода → задержка 30 с; причина отказа не раскрывается |
| BR-RULE-06 | Категории имеют один уровень вложенности; удаление категории не удаляет записи |
| BR-RULE-07 | Один TOTP-секрет на запись; время берётся из системных часов |
| BR-RULE-08 | Экспорт/импорт требуют повторного ввода мастер-пароля |
| BR-RULE-09 | Сетевые функции (HIBP, проверка обновлений) включаются только явным согласием пользователя |
| BR-RULE-10 | Заметка — не более 2000 символов; журнал событий не содержит секретов |

## 6. Границы проекта

**Входит:** разблокировка/2FA, генерация, CRUD записей, категории, поиск, избранное, заметки, автозаполнение, TOTP, бэкап/восстановление, импорт CSV, экспорт зашифрованного JSON, аудит паролей, RU/EN UI, локальный журнал, установщики Windows/Linux.

**Не входит в v0.1:** облачная синхронизация и аккаунты, командный доступ и передача паролей, мобильные приложения, расширение браузера, биометрия и FIDO2, хранение платёжных данных, ИИ/МО, macOS в R1, внешний SIEM и платная поддержка.

Диаграмма вариантов использования: [img/use-case-diagram.png](img/use-case-diagram.png).

## 7. Критерии успеха курсового проекта

1. Все 10 бизнес-требований имеют трассировку к REQ и методу верификации (100 %).
2. Новый пользователь создаёт хранилище, генерирует пароль и находит запись ≤ 60 с без инструкции.
3. В файле `vault.knx` и в логах отсутствуют открытые пароли и TOTP-секреты (проверка ревьюером).
4. Все сценарии R1/R2 работают при отключённой сети.
5. SRS заполнен на русском и английском языках; графическая часть сохранена в PNG из модели SysML v2.

## 8. Риски и допущения

| Риск | Вероятность | Мера |
|------|-------------|------|
| Потеря мастер-пароля | средняя | обязательный ключ восстановления и предупреждение при создании (BR-RULE-02) |
| Конфликт глобальной горячей клавиши | средняя | настройка комбинации и резервный вариант через буфер обмена (допущение A-06) |
| Расхождение системных часов | низкая | предупреждение и допуск ±1 шаг TOTP |
| Недоступность HIBP/GitHub | высокая | функции опциональны, локальный аудит работает офлайн |
| Несовместимость JavaFX/Java 17 | низкая | PoC-1 до начала R1 |

Полный реестр допущений — [srs-template.md](srs-template.md), раздел 2.5.
